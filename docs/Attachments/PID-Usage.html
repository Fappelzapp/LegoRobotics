PID-Kit · so benutzt du es

Ein File, sechs Befehle. Du sagst wo du hin willst — die Datei sorgt dafür, dass du dort landest.

Python · PyBricks · SPIKE Prime

1. Loslegen in 4 Schritten

  1. PyBricks Code öffnen → + → neues Python-File → Name vergeben.
  2. Den gesamten Inhalt von src/PID.py hineinpasten.
  3. Unter def mission(): deinen Weg schreiben (oder erstmal demo() stehen lassen).
  4. Run drücken. main() startet automatisch und garantiert stop_all() bei jedem Fehler.
Laptop-Import funktioniert ohne Hub: die Datei lädt nicht und bewegt nichts — ideal für Tests auf dem PC.

2. Die Befehle (mit Einheiten)

motors_pid(h, s, cm)
Fahren mit gyro-Kurskorrektur. h = Grad · s = mm/s (- = Rückwärts) · cm = cm (immer positiv)
ausrichten1(h) / ausrichten2(h)
An Ort drehen, absolut. 1 = sanft, 2 = schnell. Kürzester Weg, ±180°.
motors_kurve1(h, s, d)
Fahren & drehen bis Zielwinkel. d = Körperrotation in Grad/s (kein Prozent!)
timed_straight(dps, ms)
Geradeaus für eine feste Zeit. Für "schieben bis etwas passiert".
stop_all()
Bremst Räder + beide Module, auch wenn ein Motor abgesteckt ist.
wait_for_start()
Wartet auf frische Rechts- → Links-Taste, ohne die CPU zu versengen.

3. Mini-Mission als Vorlage

def mission():
    wait_for_start()
    motors_pid(0, 400, 40)          # 40 cm gerade, Kurs 0°
    ausrichten2(90)                 # kürzeste Drehung auf 90°
    motors_pid(90, 400, 30)        # 30 cm weiter, noch 90°
    motors_pid(90, -200, 20)       # 20 cm zurück, noch 90°
    ausrichten2(0)                 # um 180° zurückdrehen
    motors_pid(0, 0, 0)            # (sicherheitshalber)
Einheiten sind keine Kleinigkeit: amount = cm, immer positiv · Drehwinkel = Grad, absolut · Speed = mm/s · Rückwärts über negatives Speed · Drehrate = Körper-deg/s, nie ein Prozentwert.

4. Einstellungen (oben im File)

WertSinnStatus
WHEEL_DIAMETER_MM = 49.5Radgröße für Encoder/Speedgemessen 2026-11-04

LEFT_PORT / RIGHT_PORT / …Sensoren/Motor-Portsgemessen, aus der Paste

Alles andere (Ports, Toleranzen, Limits) steht mit Notiz daneben dran, ob es gemessen oder geschätzt ist. Schätzwerte niemals einstellen, weil "es passt besser" — zuerst messen.

5. Don't touch

  • HeadingPID, Motion, configure, setup_hardware, wait, stop_all — Kontrollgesetz + Inbetriebnahme. Änderungen ändern das Steuerungsverhalten.
  • Sicherheitsnetz — "wird schon" ist keine Strategie. Ist irgendetwas nach 10 s ohne Fortschritt, wirft die Datei einen Fehler und stoppt alles.

6. Was es nicht kann

Keine Linienverfolgung, keine Sensoren, keine Rückmeldung außer Heading/Encoder-Distanz. Brauchst du etwas Reaktives (Ultraschall < X cm), fügst du den Sensor in setup_hardware() ein und fragst ihn in mission() in einer Schleife ab:

from pybricks.pupdevices import UltrasonicSensor
from pybricks.parameters import Port

# in setup_hardware():
sonar = UltrasonicSensor(Port.C)

# in mission():
while sonar.distance() > 120:
    motors_pid(0, 300, 5)    # 5 cm vorwärts und neu prüfen
Golden Rule: amount = cm, Speed = mm/s, Drehwinkel = Grad. amount immer positiv — Rückwärts über negativen Speed. Jede PID-Bewegung bremst automatisch, du kannst sie also direkt hintereinander schreiben.
